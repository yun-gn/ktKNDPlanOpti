# ktKNDPlanOpti

KT 요금제 상담 직원용 화면입니다. 고객 한 명의 요금제를 검토하는 **상담** 화면과 고객 전체를 집계해 보는 **운영 대시보드**로 이루어져 있고, 분석은 n8n 워크플로우 `요금제 개인화 워크플로우`가 합니다.

```
브라우저 ── index.html (상담) ── /api/chat ── server.js ── n8n JSON Webhook ── 요금제 검토 / 후속 질문
         └─ operation-dashboard.html (운영) ───────────────── n8n dashbord Webhook (브라우저가 직접 호출)
```

## 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 상담 화면. 고객 선택, 분석 기간, 채팅, 추천 질문 |
| `operation-dashboard.html` | 운영 대시보드. 집계·가명 데이터를 OPS 쿼리로 조회 |
| `server.js` | 두 페이지를 제공하고 `/api/chat`을 n8n으로 전달합니다 (의존성 없음) |
| `package.json`, `railway.json` | `npm start`로 실행. Railway가 같은 명령으로 배포합니다 |
| `kt-chat-connected.html` | 예전 발표용 데모 (현재 사용하지 않음) |

## 실행

```bash
npm start
```

`http://localhost:3000`에서 상담 화면이, `/operation-dashboard.html`에서 운영 대시보드가 열립니다. `file://`로 직접 열면 `/api/chat`이 없어 답변을 받지 못합니다.

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | Railway가 넣어 줍니다 |
| `CHAT_URL` | n8n `Recommendation Webhook1` (JSON) | 상담 화면이 실제로 쓰는 주소 |
| `CHAT_STREAM_URL` | n8n `Webhook (stream)1` | `/api/chat?stream=1`용. 현재 화면은 쓰지 않습니다 (아래 참고) |
| `CHAT_AUTH` | 없음 | n8n Webhook에 인증을 켰을 때의 `Authorization` 헤더 값 |

`server.js`는 시작할 때 두 HTML을 읽어 둡니다. HTML을 고친 뒤에는 서버를 다시 시작하세요.

## 상담 화면 (`index.html`)

화면 전체를 세 칸으로 씁니다: **왼쪽** 고객 선택·분석 기간·사전 정보, **가운데** 검토 보고서, **오른쪽** 후속 질문 채팅. 1080px보다 좁으면 왼쪽은 위로 올라가고, 위쪽 **보고서 / 대화** 버튼으로 가운데와 오른쪽을 오갑니다.

1. **고객 선택**: 고객 ID(`U` + 숫자 5자리)를 입력하고 확인하거나, 후보 고객 4명(적정 유지 / 업셀 / 다운셀 / 결합 후보) 중 하나를 누릅니다. 왼쪽 **사전 정보**는 분석 전에 알고 있는 값(2026-10-02 조회)만 보여 줍니다. 후보가 아닌 ID는 ID만 표시합니다.
2. **분석 기간**: 1·3·6·12개월 버튼이나 날짜로 정합니다 (데이터는 2025-10-24부터).
3. **한 대화 = 한 분석**: 검토를 시작하면 보고서가 가운데에 열리고 그 상담의 기간은 잠깁니다. 다른 기간이나 다시 분석은 **새 대화**에서 합니다. 채팅에는 보고서 요약 한 줄만 남고, 이어지는 질문은 그 보고서를 바탕으로 답합니다.
4. **검토 보고서** (가운데): n8n 응답의 `review`(review-v1) 구조화 데이터로 그립니다.
   - 위쪽 숫자 카드: 현재 최종 청구, 가족 전체 기준 최저 선택지, 본인 청구 기준 최저 선택지
   - 유의사항: 한 줄씩 줄여 보이고, **전체 보기**로 펼칩니다
   - 탭: **선택지 비교**(가정 바꿔 보기 + 표, 행을 누르면 포함 혜택·별도 구독·결합·계산식) / **사용량**(월별 막대, 콘텐츠 분류, 서비스별 사용과 포함 선택지) / **가족결합** / **보고서 원문**
   - `review`가 없거나 아래 확인에 실패하면 보고서 마크다운(`output`)을 그대로 보여 줍니다.
5. **가정 바꿔 보기**: n8n이 계산한 선택지 값에서 다음만 화면이 다시 더하고 뺍니다. 요금제 후보와 결합 규칙은 바꾸지 않습니다.
   - 선택약정 25% 적용/미적용 (`selective`)
   - 본인 결합 할인 최소/최대 (기준 회선 동률·할인 배분으로 범위가 나올 때, `discount[0]` / `discount[1]`). 가족 합계는 바뀌지 않습니다
   - 계속 쓸 유료 서비스: 끊을 서비스의 정가를 별도 구독액(`extra`)에서 뺍니다
   - 고정 가정: **5G 단말**(하향 정산 표시를 "47,000원 이상: 베이직코스면 정산 / 미만: 정산 대상"으로 정함), **인터넷 약정 12개월**(요청 본문에 `contractMonths: 12`를 보냄)
   - 보고서를 받으면 화면 계산을 보고서 값(`final`, `saving`, `family_monthly_change`, `final_selective`)과 먼저 맞춰 봅니다. 하나라도 다르면 이 기능을 끕니다.
6. **추천 질문**: 답변 아래에 다음 질문 버튼이 붙습니다. 보고서의 값에서 규칙으로 만들고, n8n이 답변 끝에 ` ```suggestions ` 블록(한 줄에 질문 하나)을 보내면 그것을 우선합니다.
7. **운영** 버튼은 같은 탭에서 운영 대시보드로 이동합니다. 이 페이지를 떠나면 화면의 대화는 사라집니다.

n8n으로 보내는 요청 본문:

```json
{ "action": "sendMessage", "sessionId": "<고객별 상담 ID>", "chatInput": "...", "userMessage": "...",
  "userId": "U00603", "startDate": "2026-04-06", "endDate": "2026-10-06", "intent": "", "contractMonths": 12 }
```

- `sessionId`는 고객마다 따로 만들고, **새 대화**를 누르면 새로 만듭니다.
- `intent`는 "이 고객의 요금제가 적정한지 검토해줘" 시작 버튼만 `review`이고 나머지는 비워 둡니다. 비어 있으면 n8n이 저장된 분석이 있는지로 판단합니다.

## n8n 워크플로우

`요금제 개인화 워크플로우`의 상담 흐름:

```
Recommendation Webhook1 / Webhook (stream)1
  → Normalize Request1          (userId·기간 검증, sessionId·intent 보존)
  → Find Saved Analysis         (Data Table analysis_cache: 같은 sessionId·같은 기간)
  → Decide Route → Follow-up?
      ├─ 후속 질문 → Follow-up Agent → Respond to Webhook1
      └─ 새 분석   → Collect Required Evidence1 → … → Compose Review Output
                        ├→ Respond to Webhook1
                        └→ Prepare Cache Row → Save Analysis (analysis_cache)
```

- **새 분석**이 되는 경우: 그 상담의 첫 질문, 분석 기간을 바꾼 뒤의 질문, `intent: "review"`, 새 대화.
- **Follow-up Agent**는 도구 없이 저장된 분석(보고서와 월별·서비스별·콘텐츠별 사용량, 선택지 데이터)과 이전 대화만으로 답합니다. 분석에 없는 값은 지어내지 않고 없다고 답합니다. 답변 하나에 Gemini 호출 한 번, 2초 안팎입니다.
- **기간 제한**: 달력 기준 최대 13개월까지 받습니다 (완전한 12개월 + 진행 중인 이번 달). 이번 달은 분석에서 빠집니다.
- **스트리밍을 쓰지 않는 이유**: 보고서를 보내는 `Respond to Webhook1`(v1.4)은 스트리밍 응답에 쓰지 못합니다. 스트리밍으로 받으면 보고서 대신 중간 Agent의 JSON만 옵니다. 그래서 화면은 `stream: false`로 JSON Webhook을 씁니다. 검토는 10초 안팎이라 n8n Cloud의 약 100초 제한에 걸리지 않습니다.

## 요금제 최적화 (`Evaluate Options`)

`Evaluate Options` 노드가 선택지와 금액을 계산합니다. 계산은 규칙으로만 합니다. AI는 숫자를 만들지 않습니다.

```
Prepare Snapshot1 → Bundle Rules Needed?
  ├─ 예 (가족이 KT 인터넷 사용 중) → Fetch Bundle Rules → Evaluate Options
  └─ 아니요                         → Evaluate Options
Evaluate Options → … → Build Review Dataset → … → Compose Review Output
```

### 1. 선택지

1. 요금제와 혜택 조합을 모두 만듭니다. 판매가 끝난 요금제는 넣지 않습니다 (6항).
2. 제공량이 최대 월 사용량 × 1.1보다 적은 요금제는 뺍니다.
3. 요금제에 없는 유료 서비스는 정가로 따로 구독한다고 봅니다.
4. 기준(최저 청구, 최저 월정액, 최소 변경, 최대 혜택, 여유 용량, 균형)마다 선택지를 하나씩 고릅니다.

### 2. 가족결합 할인

- 가족이 있고 KT 인터넷이 `ACTIVE`일 때만 계산합니다.
- 규칙은 `dw_personalization.internet_bundle_discount_rules`와 `premium_family_discount_rules`에서 읽습니다.
- 본인 회선만 바꿉니다. 다른 가족 회선의 요금제는 그대로 둡니다.
- 프리미엄 가족결합과 인터넷·모바일 결합을 계산합니다. 각각 총액과 정액을 계산하고, 할인이 큰 쪽만 보여 줍니다.
- 이미 결합한 가족은 지금 결합 종류를 유지합니다. 프리미엄 조건(월정액 77,000원 이상 2회선)이 깨지면 총액/정액 결합으로 자동 전환됩니다.
- 최종 청구액 = 할인 전 청구액 − 본인 회선 결합 할인. 할인이 범위이면 작은 값을 뺍니다.
- 기준은 가족 전체 금액으로 고릅니다. 프리미엄 25% 할인이 다른 회선에서 본인 회선으로 옮겨 가는 것은 절약으로 보지 않습니다.
- 인터넷 할인은 인터넷 요금에서 빠집니다. 최종 청구액에 넣지 않습니다.
- 규칙을 읽지 못하면 결합 할인 없이 계산하고, 유의사항에 그 사실을 적습니다.

### 3. 인터넷 약정기간

- 기준값은 12개월입니다. 12개월은 할인이 가장 작습니다.
- 요청 본문에 `contractMonths`(12, 24, 36)를 넣으면 그 값으로 계산합니다. 상담 화면은 12를 보냅니다 (12개월 고정).
- 모든 선택지를 36개월로 한 번 더 계산합니다. 결과는 유의사항 문구에만 씁니다.
  - 결합 종류와 방식이 같으면: "36개월 약정이면 가족 할인이 커질 수 있습니다."
  - 결합 종류나 방식이 바뀌면: "실제 할인액은 달라질 수 있습니다."

### 4. 선택약정 25%

- "선택약정 적용 시" 열 = 청구액 − 월정액 × 25%. 결합 할인과 중복 적용합니다.
- 기준을 고를 때는 넣지 않습니다. 고객의 선택약정 가입 여부는 데이터에 없습니다.
- 선택약정을 받으면 최저 청구 선택지가 바뀌는 경우, 그 선택지를 추가하고 차이를 유의사항에 적습니다.

### 5. 주의 표시

선택지 표의 **주의** 열에 다음을 표시합니다.

| 표시 | 조건 | 뜻 |
|---|---|---|
| 하향: 베이직코스면 정산 | 새 월정액 47,000원 이상 | 심플코스는 면제입니다. 베이직코스는 약정 730일 안이면 정산합니다 |
| 하향: 5G 단말이면 정산 | 새 월정액 20,000원 이상 47,000원 미만 | 5G 단말은 심플코스도 정산합니다 |
| 하향: 정산 대상 | 새 월정액 20,000원 미만 | 모든 단말이 정산합니다 |
| 결합 할인 월 −X원 | 가족 결합 할인 합계가 줄어듦 | 금액은 "가족 전체 현재 대비"에 이미 들어 있습니다 |
| 결합 할인 변동 (미계산) | 결합 가족 + 규칙 조회 실패 + 월정액 변경 | 할인 변화를 계산하지 못했습니다 |

- 공통지원금 차액정산액 = (현재 요금제 지원금 − 새 요금제 지원금) × 남은 약정일 ÷ 550일.
- 지원금 금액, 코스, 약정 시작일은 데이터에 없습니다. 그래서 해당 여부만 표시하고 금액은 계산하지 않습니다.
- 결합 할인 감소는 이미 결합한 가족만 계산합니다. 기준은 지금 결합의 가족 할인 합계입니다.

### 6. 판매 종료 요금제

- 판매가 끝난 요금제는 새 선택지로 내지 않습니다. 고객은 현재 요금제를 유지할 수 있습니다.
- 목록은 `CFG.unavailablePlanIds`입니다. 요금제 카탈로그에 `is_available = false` 또는 `sale_status`(`CLOSED`, `DISCONTINUED`) 열이 생기면 그 값도 따릅니다.
- **현재 목록은 비어 있습니다.** 카탈로그에 판매 상태 정보가 없습니다. 보고서는 "모든 요금제를 판매 중으로 봤다"고 적습니다.

### 가정

- 고객은 현재 요금제를 6개월 넘게 유지했습니다.
- 요금제 변경은 신청하면 자동으로 적용됩니다.
- 해지와 선택약정 비대상 요금제로의 이동은 없습니다. 그래서 선택약정 반환금은 없습니다.
- 초이스 혜택 변경(예: Netflix → YouTube)은 무료입니다.
- 단말 지원금, 할부, 카드 할인은 기기를 바꿀 때의 혜택입니다. 요금제 변경 계산에 넣지 않습니다.

### 계산에서 뺀 변수

| 변수 | 이유 | 보고서 처리 |
|---|---|---|
| 공통지원금 차액정산 금액 | 지원금 금액·코스·약정 시작일 없음 | 해당 여부만 표시 |
| 단말 종류 (5G / LTE) | 데이터 없음 | 정산 기준을 두 단계로 표시 |
| 현재 결합의 총액/정액 방식 | 데이터 없음 | 더 유리한 방식이라고 가정 |
| 기준 회선 동률 시 나이 | 데이터 없음 | 본인 회선 할인을 범위로 표시 |
| 청소년 결합 혜택 (D004) | 나이·보호자 정보 없음 | 계산에서 뺌 |
| 회선 명의자·보호자 | 데이터 없음 | 결합 변경 결정권을 보지 않음 |

## 운영 대시보드 (`operation-dashboard.html`)

n8n `dashbord` Webhook에 `{ query_id, parameters }`를 POST해 OPS 쿼리 결과(`{ ok, query_id, rows }`)를 받습니다. 브라우저가 n8n을 직접 부르며, Webhook에 `allowedOrigins: *`가 설정돼 있습니다. 오른쪽 위 **상담** 버튼으로 상담 화면에 돌아갑니다.

- 인터넷 약정 12개월을 기준으로 계산하고, 36개월 결과는 유의사항에 적습니다.
- "선택약정 적용 시" 열을 추가했습니다.
- "주의" 열을 추가했습니다: 하향 시 공통지원금 차액정산 가능성, 결합 할인 감소액.
- 판매 종료 요금제를 선택지에서 빼는 필터를 넣었습니다 (목록은 아직 비어 있음).
- Follow-up Agent가 결합 할인과 "주의" 열을 설명합니다.

## 2026-10-06 변경 내역

- 상담 화면: 고객 ID 입력 단계를 넣고, 후보 고객 카드 4장을 설명과 함께 되살렸습니다. 스트리밍·마케팅 토글을 없앴습니다.
- 추천 질문 버튼을 추가했습니다.
- n8n: 모든 질문이 전체 분석을 다시 돌리던 것을, 저장된 분석을 다시 쓰는 후속 질문 경로로 나눴습니다 (`analysis_cache`, `Follow-up Agent`).
- 보고서 대신 JSON이 보이던 문제를 고쳤습니다: 화면을 JSON 응답으로 되돌렸습니다.
- 12개월 기간이 항상 실패하던 문제를 고쳤습니다 (13개월까지 허용).
- 운영 대시보드를 저장소에 넣고 상담 화면과 서로 오가게 연결했습니다.

## 알려진 제한과 남은 일

- 후속 질문은 저장된 분석에 있는 값만 답합니다. 최근 7일·30일 사용량, 결합 외 할인 상태처럼 분석에 없는 값은 "분석에 없다"고 답합니다. 조회가 필요하면 별도 단계로 추가해야 합니다.
- 분석은 상담(sessionId)별로 저장됩니다. 같은 고객·같은 기간이라도 새 대화에서는 다시 분석합니다.
- 데이터가 2025-10-24부터라 12개월 분석의 2025-10은 실제로는 일부만 있는 달인데, 보고서는 완전한 달로 셉니다 (분석 파이프라인에서 확인 필요).
- 추천 질문 버튼에 마우스를 올리면 보이는 "근거 조회: PERS_…"는 데이터 출처를 가리킬 뿐, 후속 질문이 그 쿼리를 실행하지는 않습니다.
- 사용하지 않는 n8n 테스트 자료: `요금제 개인화 · 후속 질문 라우팅 (테스트)`, `요금제 개인화 · 카탈로그 쿼리 실행 (Tool)` 워크플로우(둘 다 비활성), `analysis_cache`의 테스트 행 몇 개. 정리해도 됩니다.
